# MES Middleware 設備端模擬器

## 🎯 功能簡介

**設備端模擬器** 用於模擬生產設備向 **MesMiddleware.Service** 發送檢測數據,方便進行整合測試。

### 核心功能

✅ **手動發送**: 自定義 TraceCode/LotNo/Result 手動發送單筆數據
✅ **批量發送**: 一次發送 1-100 筆自動生成的測試數據
✅ **自動發送**: 定時自動發送數據 (可設定間隔 1-60 秒)
✅ **隨機生成**: 一鍵生成符合真實格式的 TraceCode, LotNo, Result
✅ **通訊監控**: 查看發送歷史、響應狀態、錯誤訊息
✅ **統計功能**: 實時顯示總數、成功數、失敗數

```bash
cd src/MesMiddleware.Service

```


## 📋 使用方式

### 🖊️ 手動發送 (左側面板)

**功能**: 自定義數據手動發送

**步驟**:
1. 點擊 **生成 TraceCode** → 自動生成 `TRACE-20241120-0001`
2. 點擊 **生成 LotNo** → 自動生成 `LOT-202411-023`
3. 點擊 **隨機結果** → 自動生成 `OK` 或 `NG` (80% 良品率)
4. 點擊 **🚀 發送數據** → 立即發送到 Middleware

**TraceCode 格式**: `TRACE-日期-流水號` (例: `TRACE-20241120-0001`)
**LotNo 格式**: `LOT-年月-批次號` (例: `LOT-202411-023`)
**Result 選項**: `OK` (良品) 或 `NG` (不良品)

---

### 📦 批量發送 (中間面板)

**功能**: 一次發送多筆測試數據

**設定**:
- **數量**: 1-100 筆 (滑桿調整)
- **間隔**: 0-1000 毫秒 (滑桿調整)

**步驟**:
1. 調整數量滑桿到想要的數量 (例: 50 筆)
2. 調整間隔滑桿 (例: 100ms,避免過快發送)
3. 點擊 **📤 批量發送**
4. 等待發送完成彈窗提示

**注意**: 間隔設為 0 會連續快速發送,建議設為 100ms 以上

---

### 🔄 自動發送 (右側面板)

**功能**: 定時自動生成並發送測試數據

**設定**:
- **間隔**: 1-60 秒 (滑桿調整)

**步驟**:
1. 調整間隔滑桿 (例: 5 秒)
2. 點擊 **▶️ 啟動自動發送**
3. 按鈕變為 **⏹️ 停止自動發送** (紅色)
4. 再次點擊停止

**應用場景**: 長時間壓力測試、模擬持續生產

4. 觀察統計: 成功數應該 = 100

1. 設定自動發送間隔 = 5 秒

4. 重新啟動 MesMiddleware.Service
5. 確認自動恢復正常發送

## 🔧 數據生成演算法

### TraceCode 生成規則

```
格式: TRACE-{日期}-{流水號}
日期: yyyyMMdd (例: 20241120)
流水號: 0001-9999 (4位數字,自動遞增)
範例: TRACE-20241120-0042
```

### LotNo 生成規則

```
格式: LOT-{年月}-{批次號}
年月: yyyyMM (例: 202411)
批次號: 001-100 (3位數字,隨機)
範例: LOT-202411-023
```

### Result 生成規則

```
良品率: 80% 為 OK
不良率: 20% 為 NG
NG 原因: 隨機選擇「尺寸超差、表面刮傷、孔位偏移、毛邊過大」等
```

### 完整檢測記錄結構

```json
{
  "rowNo": "1",
  "procName": "鑽孔",
  "devName": "鑽孔機-01",
  "userName": "操作員A",
  "workClass": "日班",
  "traceCode": "TRACE-20241120-0001",
  "lotNo": "LOT-202411-023",
  "paramData": [
    { "name": "孔徑", "value": "9.87" },
    { "name": "深度", "value": "4.72" }
  ],
  "benchmarks": [
    { "name": "孔徑", "upperLimit": "10.0", "lowerLimit": "9.5" }

```

## 🐛 常見問題

### Q1: 連接測試失敗 (紅燈)?

**解決方案**:
1. 確認 MesMiddleware.Service 是否運行中
2. 檢查服務器地址是否正確 (`http://localhost:5100`)
3. 查看 Middleware.Service 日誌是否有錯誤

### Q2: 發送失敗,錯誤「網絡錯誤」?

**解決方案**:
1. MesMiddleware.Service 可能已停止
2. 防火牆可能阻擋 5100 端口
3. 重新測試連接

### Q3: 批量發送太慢?

**解決方案**:
1. 減少間隔毫秒數 (例: 從 1000ms 改為 100ms)
2. 或設為 0ms 連續發送 (注意可能造成服務器壓力)

### Q4: 自動發送無法停止?

**解決方案**:
1. 再次點擊 **⏹️ 停止自動發送** 按鈕
2. 如無法停止,關閉應用程式重新啟動
